# Partial multi-session Alpha journeys 1

`irgs-alpha-journeys-v1` provides separate actor instructions, evaluator-only
expectations and a bounded evidence schema for two distinct campaign contexts.
It binds `alpha_contexts_v1` by exact manifest hash and retains all earlier
fixtures and selectors. A schema validates evaluator claims, never authorizes
an action or proves that an Alpha gate has passed.

explicit compatibility override, not an App pin update or joined approval.

The new explicitly reviewed fictional `quay-contact-v1` variant supplies one
legitimately received fictional participant. Through normal HTTP preview and
creation the actor speaks exact testimony without assumed NPC reply or consent,
observes, attempts an unsuccessful shortcut, takes the alternate route and
delivers the conserved dispatch. A separately submitted second delivery fails
without manufacturing another dispatch, consuming its selected ten-second span.
Results survive host restart and exact retry;
foreign actor substitution is rejected. The existing fictional R00 case reviews
creation, walks, founds and completes finite shelter work across host restart.
Both cases exercise an identical-byte Trash restore through the actual App API,
then recover original results without repeating effects. Routine provider
dispatch and direct transport are forbidden.

The independent test's partial evidence retains unmet NPC decision, institutional
reaction, needs/recovery, selected consequential conflict, live-provider and
older-restore-branch requirements. An identical-byte restore does not qualify
restoring an older branch or prove that future receipts are fenced there. The
selected speech has no invented elapsed duration or automatic NPC decision.
Different campaign contexts and repeated actions do not by themselves establish
sustained Alpha play. No user save, private fixture or live provider participates.
